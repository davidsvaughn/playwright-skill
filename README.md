# playwright-skill

House rules for browser work with Microsoft's `playwright-cli` on David's machine, packaged as a Claude Code skill.
`SKILL.md` is the skill; this file is the setup and maintenance guide for the human.

Until 2026-09-16 this repo was a fork of `willmarple/playwright-skill`, a wrapper around `playwright-cli` (session files, context capture, CSS-selector helpers).
A head-to-head (`test/README.md`) showed agents do the same QA work with the CLI's own commands, so the wrapper was retired and this repo was restarted from scratch.

## How it fits together

| Piece | What it is | Maintained by |
|---|---|---|
| `@playwright/cli` (global npm package) | the browser tool | `npm install -g` |
| `~/.claude/skills/playwright-cli/` | the CLI's own agent reference, generated by the CLI | `playwright-cli install --skills -g`; never edit |
| `~/.claude/skills/playwright-skill` (symlink to this repo) | house rules: session names, logins, debugging, output gotchas | this repo |
| `~/.local/state/playwright-auth/<profile>.json` | saved login state per site (dir 700, files 600) | `state-save`, see `SKILL.md` section 3 |
| each project's `CLAUDE.md` | base URL, profile name, site-specific selectors | the project |

The global `CLAUDE.md` says to use `playwright-cli` for browser work and load both skills.
Everything else about browsers lives here, so a change to the rules is a commit in this repo.

## Install

```bash
git clone git@github.com:davidsvaughn/playwright-skill.git ~/code/davidsvaughn/playwright-skill
ln -sfn ~/code/davidsvaughn/playwright-skill ~/.claude/skills/playwright-skill
npm install -g @playwright/cli@latest
playwright-cli install --skills -g          # writes ~/.claude/skills/playwright-cli
grep -q '^.playwright-cli/$' ~/.gitignore || echo '.playwright-cli/' >> ~/.gitignore
```

## Upgrading `playwright-cli`

```bash
npm view @playwright/cli version            # latest release
npm install -g @playwright/cli@latest
rm -rf ~/.claude/skills/playwright-cli      # the installer merges into an existing dir and keeps stale files
playwright-cli install --skills -g
```

Then recheck `SKILL.md`: sections 1, 4 and 5 describe CLI behaviour that changes between releases.
`test/brief.md` is the check: one fresh subagent, the two skills, the test app.
`test/measure.sh` times the same flow without an agent.

## Recovery

| Problem | Do |
|---|---|
| `The browser 'default' is not open` | the command lacks `-s=<name>` |
| `The browser '<name>' is not open` after a pause | a headless session timed out after an hour idle; `open` again and `state-load` if needed |
| a headed window is stuck | `playwright-cli -s=<name> close`, then `open` again; `kill-all` only if asked, it closes every agent's browser |
| the site shows its sign-in page after `state-load` | the saved session expired; ask the user to sign in in the headed window and `state-save` again |
| an element has no ref in the snapshot | use a CSS selector or locator string in place of the ref (`SKILL.md` section 6) |
